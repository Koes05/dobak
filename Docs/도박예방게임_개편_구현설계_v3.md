# 도박 예방 교육 게임 개편 구현 설계 v3

## 1. 프로젝트 정의

이 게임은 도박 결과를 맞히거나 도박을 잘하는 게임이 아니다.

플레이어는 7일 동안 제한된 시간을 사용해 학교, 숙제, 알바, 수면과 인간관계를 유지하면서 도박으로 생긴 손실과 유혹에 대응한다.

핵심 질문은 다음과 같다.

> 빠르게 손실을 복구할 수 있다는 유혹 앞에서 무엇을 포기하고, 그 선택이 다음 날의 일상에 어떤 결과를 남기는가?

도박은 별도 사이트나 미니게임으로 조작하지 않는다. 메시지, 내레이션, 금액 카운트, 시간 경과, 화면과 음향 연출로 표현한다. 플레이어가 조작하는 대상은 확률이 아니라 `그만두기`, `한 번 더 하기`, `일상으로 돌아가기`, `도움을 요청하기`이다.

## 2. 게임의 코어

### 플레이어 목표

- 이번 주의 필수 일정을 최대한 지킨다.
- 도박으로 잃은 돈을 어떻게 처리할지 결정한다.
- 사람들과의 약속과 신뢰를 유지한다.
- 상황이 악화됐을 때 숨길지 도움을 요청할지 선택한다.

### 핵심 루프

```text
오전 7시 하루 시작
→ 수면 결과 연출
→ 오늘 일정과 마감 확인
→ 학교/숙제/알바/수면/도박 관련 선택
→ 실제 시간·돈·관계·일정 상태 변화
→ 선택에 따른 메시지와 후속 장면
→ 하루 정산
→ 다음 날
```

### 게임다운 선택의 기준

모든 주요 선택은 다음 다섯 요소를 가져야 한다.

1. 비교 가능한 다른 선택지가 있다.
2. 즉시 얻는 보상이나 안도감이 있다.
3. 지연되어 돌아오는 비용이 있다.
4. 게임 상태가 실제로 바뀐다.
5. 다음 장면 또는 엔딩 내용이 달라진다.

이 조건을 만족하지 못하는 이벤트와 기능은 제거한다.

## 3. 유지·축소·삭제할 기능

### 유지

- 오전 7시 기준 일차 전환
- 현재 시각과 행동별 시간 소모
- 학교, 숙제, 알바, 수면 일정
- 체크리스트와 마감
- 메시지 앱
- 은행 앱
- 공부 기능
- 장소 이동 시간
- 하루 정산과 엔딩

### 축소

- 지도 앱은 경로 탐색 게임이 아니라 이동 시간 확인과 장소 선택에 집중한다.
- 공부 문제는 매일 반복되는 분량을 줄이고, 과제 스토리를 진행하는 행동으로 사용한다.
- 홈 화면에는 현재 시간과 오늘 일정만 표시한다. 빚, 관계도, 도박 단계 등의 내부 수치는 직접 노출하지 않는다.

### 삭제

- 도박 사이트 앱
- 슬롯머신과 베팅 금액 선택
- 충전과 환전 UI
- 사이트 포인트를 관리하는 기존 게임플레이
- SNS 앱
- 맥락 없는 랜덤 메시지
- 예전 먹튀·환전·도박 횟수 기반 엔딩
- 코드에 직접 적혀 있는 시나리오 대사와 분기

SNS는 남는 시간을 소비하는 것 이외의 목적이 없으며, 7일 고정 시나리오에서는 메시지와 도박 유혹이 같은 역할을 더 직접적으로 수행하므로 제거한다.

## 4. 7일 구성

### DAY 1: 평범한 일상과 유입

- 학교와 조별 과제를 소개한다.
- 민재가 신규 가입 포인트와 친구추천을 제시한다.
- 거짓 거절 선택지를 주지 않고 첫 도박까지 프롤로그로 진행한다.
- 첫 승리와 실제 입금으로 도박을 매력적으로 보여준다.
- 추가 수익과 수면 중 첫 선택을 준다.

### DAY 2: 쉬운 돈과 일상의 대비

- 학교 출석 또는 결석을 선택한다.
- 출석하면 서연의 과제 자료와 숙제 도움을 얻는다.
- 결석하면 시간이 생기지만 숙제 시간이 증가하고 담임 연락이 온다.
- 숙제 2시간과 빠른 도박 수익을 비교한다.
- 도박을 계속하면 수면 시간이 줄어든다.

### DAY 3: 첫 손실과 복구 심리

- 조별 과제 역할을 정한다.
- 민재가 지금까지 딴 돈이니 잃어도 본전이라는 논리로 큰 금액을 권한다.
- 도박을 거절하면 민재의 수익 자랑이 다음 유혹으로 남는다.
- 도박하면 첫 큰 손실이 발생한다.
- 손실을 인정할지 복구를 시도할지 선택한다.
- 도박에 쓴 시간 때문에 숙제 또는 수면을 포기하게 된다.

### DAY 4: 조별 과제 마감

- 학교 출석 여부에 따라 과제 소요 시간이 달라진다.
- 오후 9시 마감과 필요한 시간을 정확히 알려준다.
- 과제와 손실 복구를 같은 시간대에 배치한다.
- 도박 중에도 현재 시각과 마감까지 남은 시간을 보여준다.
- 제출 성공 또는 실패가 서연과 담임의 후속 장면으로 이어진다.

### DAY 5: 관계와 알바 준비

- 과제 결과에 따라 서연의 반응이 달라진다.
- 엄마와 저녁을 먹고 다음 날 알바를 준비하거나, 복구를 시도한다.
- 가족 관계를 지키면 후반 도움 요청 경로가 강화된다.
- 새벽까지 도박하면 다음 날 알바에 필요한 수면이 줄어든다.

### DAY 6: 확실한 수입과 도박의 충돌

- 오전 8시부터 오후 4시까지 카페 근무가 있다.
- 출근하면 100,000원과 매니저 신뢰를 얻고 자동으로 집에 돌아온다.
- 출근 전에 도박하면 근무 시간과 급여를 잃는다.
- 알바비를 지킬지 손실 복구에 사용할지 다시 선택한다.
- 잔액이 부족해지면 서준 또는 엄마에게 돈을 빌린다.
- 민재의 친구추천 목적이 드러난다.

### DAY 7: 누적 결과와 결말

- 빚, 결석, 과제 실패, 알바 결근에 따라 서로 다른 연락이 쌓인다.
- 일상을 지킨 경우 서연이나 매니저가 도움을 제안할 수 있다.
- 민재가 자신의 빚과 추천 보너스 목적을 인정한다.
- 마지막 손실 복구, 중단, 도움 요청을 선택한다.
- 엔딩은 마지막 버튼 하나가 아니라 일주일 동안 저장된 선택과 상태로 판정한다.

## 5. 일정별 연속 스토리

### 학교 스토리

- 출석: 서연과 조별 과제 진행, 담임 신뢰, 과제 시간 감소, 도움 경로 개방
- 결석: 자유 시간 확보, 수업 정보 누락, 숙제 시간 증가, 담임과 보호자 연락
- 누적 결석: 상담 요구, 관계 악화, 학교 관련 후일담 변화

### 숙제 스토리

- 완료: 서연과 자료 교환, 다음 장면 대사 변화, 조별 과제 성공 가능성 증가
- 미완료: 다음 날 추가 시간 필요, 서연의 부담 증가, 담임 경고
- 마감 실패: 조원과의 신뢰 손실, 엔딩 후일담 반영

### 알바 스토리

- 출근: 8시간 소모, 확실한 100,000원, 매니저 신뢰와 도움 경로
- 결근: 하루 자유 시간, 급여 없음, 다음 근무 제한
- 알바비 도박: 노동의 결과를 손실 복구에 다시 투입하는 갈등

### 수면 스토리

- 5시간 이상: 정상적인 행동 시간과 차분한 독백
- 1~4시간: 피로 연출, 공부 시간 1시간 증가, 누적 수면 부족 기록
- 0시간: `밤을 새어버렸다` 전 화면 연출, 공부 시간 2시간 증가, 밤샘 누적
- 반복 수면 부족: 학교, 숙제, 알바 장면의 대사와 결과 변화

### 도박 스토리

- 무료 포인트
- 첫 승리
- 쉬운 돈 인식
- 근접 결과와 시간 손실
- 첫 큰 손실
- 손실 추격
- 알바비 사용
- 빚 발생
- 친구추천 목적 공개
- 중단, 도움 요청 또는 붕괴

도박 결과는 핵심 구간에서 랜덤으로 결정하지 않는다. 첫 승리와 이후 손실은 시나리오 단계에 맞게 설계한다. 플레이어가 반복해서 결정하는 것은 결과가 아니라 `계속할지 멈출지`이다.

## 6. 연출 방향

### 도박 승리

- 화면 전체 금액 카운트
- 짧고 강한 성공음
- 은행 입금 알림
- 민재의 즉각적인 축하 메시지
- 버튼은 `한 번 더`를 시각적으로 먼저 인식하게 배치

### 도박 손실

- 결과 숫자가 빠르게 떨어진 뒤 정지
- 배경음과 효과음이 갑자기 사라짐
- 현재 시각이 크게 바뀌는 연출
- 놓친 일정 알림이 연속으로 도착
- 주인공의 짧은 독백 후 `그만두기 / 복구하기` 선택

### 수면 부족

- 색감과 음향을 약하게 둔화
- 전환 속도와 입력 반응은 실제로 느리게 만들지 않는다.
- 독백과 행동 소요 시간으로 피로를 표현한다.
- UI 조작을 불편하게 만들어 플레이어를 벌주지는 않는다.

### 일정 실패

- 체크리스트만 실패 처리하지 않는다.
- 관련 인물의 메시지 또는 대면 장면을 보여준다.
- 다음 행동 시간, 관계, 수입 또는 이용 가능한 선택지에 영향을 준다.

게임 재시작은 현재 상태와 `ChoiceHistory`를 모두 초기화한다. 이어하기는 마지막 장면과 선택 직전 상태를 복원한다.

## 8. CSV 실행 규칙

CSV의 각 장면은 다음 정보를 가진다.

- `scene_id`: 장면 묶음 ID
- `line_id`: 저장과 재생에 사용하는 개별 대사 ID
- `arc`: 학교, 숙제, 알바, 수면, 도박, 결과, 엔딩 구분
- `day`, `time_window`: 발생 일차와 시간대
- `trigger`, `condition`: 발생 계기와 조건
- `priority`, `once_scope`: 동시에 발생할 때의 우선순위와 반복 범위
- `speaker`, `contact`, `delivery`: 화자, 연락처, 표시 방식
- `choice_a/b_id`: 저장용 고유 선택 ID
- `choice_a/b_effects`: 실제 상태 변화
- `choice_a/b_next`: 선택 후 이동할 장면
- `enter_effects`: 장면 진입 시 자동 적용되는 변화
- `auto_next`: 선택이 없는 장면의 다음 장면
- `purpose`: 이 장면이 존재해야 하는 이유

조건식에서 `;`는 AND, `|`는 OR로 사용한다.

```text
day=4;schedule.project=missed
school_absences>=2|homework_failures>=2
```

효과 명령은 `|`로 구분한다.

```text
clock:add=120
cash:add=-70000
debt:add=50000
schedule.homework:set=complete
relation.seoyeon:add=1
counter.gamble_sessions:add=1
flag.help_requested:set=true
sleep:set=5
ending:set=help
```

코드는 대사나 특정 장면 ID를 직접 알지 않는다. 코드는 CSV의 조건을 평가하고 효과 명령을 실행하며 상태를 저장하는 역할만 한다.

## 9. 필요한 코드 구조

### GameState

현재 시간, 돈, 빚, 일정, 관계, 피로와 도박 단계를 저장한다.

### ScenarioDatabase

CSV를 읽어 `scene_id`별로 대사와 선택지를 구성한다. 로딩 단계에서 중복 ID, 없는 다음 장면, 잘못된 효과 명령을 검사한다.

### ScenarioDirector

현재 일차·시간·상태에 맞는 장면을 찾고 우선순위대로 실행한다. 한 번 발생한 장면은 `once_scope`에 따라 다시 발생하지 않게 한다.

### EffectExecutor

CSV의 효과 명령을 공통 방식으로 처리한다. 시간, 돈, 빚, 일정, 관계와 플래그를 모두 여기에서 변경한다.

### ChoiceHistory

모든 선택 ID와 선택 전후 상태를 저장한다. 엔딩 판정과 재시작, QA에도 같은 기록을 사용한다.

### ScheduleManager

오전 7시 일차 전환, 학교와 알바 마감, 과제 마감, 수면 계산을 담당한다.

### PresentationDirector

내레이션, 메시지, 대면 대화, 금액 연출, 화면 암전, 수면 부족 효과, 하루 정산을 표시한다.

### EndingResolver

마지막 선택 하나가 아니라 누적 상태로 엔딩과 후일담을 결정한다.

## 10. 엔딩 판정

### 위험 차단

- 빚 없음
- 일정 실패 1회 이하
- 도박 세션 3회 이하
- 마지막 손실 추격 거절

### 도움 요청

- `help_requested=true`
- 엄마 또는 담임에게 실제 도움 요청 선택
- 빚과 실패가 남아 있어도 진입 가능

### 미해결

- 추가 도박은 중단
- 빚 또는 일정 문제가 남음
- 누구에게도 말하지 않음

### 일상 붕괴

- 마지막 손실 추격 선택
- 또는 심각한 빚과 일정 실패가 누적된 상태에서 계속 도박

엔딩 본문 뒤에는 학교, 숙제, 알바, 수면과 관계 상태에 따른 짧은 후일담을 추가한다. 같은 도움 요청 엔딩이어도 플레이어가 무엇을 지켰는지에 따라 마지막 장면이 달라져야 한다.

## 11. 구현 순서

1. 현재 프로젝트를 별도 브랜치에 백업한다.
2. 도박 사이트, 슬롯, 충전, 환전과 예전 엔딩 판정을 비활성화한다.
3. 새 `GameState`와 저장 버전을 만든다.
4. 새 CSV 로더와 로딩 검증기를 만든다.
5. 공통 효과 실행기를 만든다.
6. `ChoiceHistory`와 이어하기·완전 초기화를 구현한다.
7. 기존 시간·학교·숙제·알바·수면 기능을 새 상태와 연결한다.
8. 메시지·다이얼로그·금액·화면 전환 연출을 연결한다.
9. DAY 1부터 DAY 7까지 순서대로 통합한다.
10. 모든 주요 선택 조합을 실제 플레이로 QA한다.

## 12. QA 기준

### 데이터 검증

- 중복된 `scene_id`, `line_id`, `choice_id`가 없는가
- 존재하지 않는 다음 장면을 참조하지 않는가
- 모든 선택에 실제 효과가 있는가
- 모든 장면에 목적이 작성되어 있는가
- 한글이 UTF-8 BOM으로 정상 표시되는가

### 플레이 검증

- 학교 결석 후 숙제와 다음 학교 장면이 실제로 달라지는가
- 숙제 미완료 후 서연과 담임의 반응이 달라지는가
- 알바 결근 시 급여와 다음 근무가 실제로 사라지는가
- 수면 시간에 따라 다음 날 공부 시간이 달라지는가
- 도박할 때 실제 시간과 잔액이 함께 변하는가
- 빚의 상대에 따라 DAY 7 메시지가 달라지는가
- 저장 후 재실행해도 같은 상태와 장면에서 이어지는가
- 재시작하면 선택 이력과 모든 상태가 완전히 초기화되는가
- 마지막 선택이 같아도 누적 상태에 따라 후일담이 달라지는가

### 화면 검증

- 태블릿 비율에서 대사와 선택지가 잘리지 않는가
- 메시지가 입력 영역을 침범하지 않는가
- 긴 문장은 말줄임표와 전체 채팅 화면에서 자연스럽게 처리되는가
- 수면, 이동, 승리, 손실 전환 중 상단 상태바와 하단 바가 유지되는가
- 화면 연출이 입력을 막거나 같은 이벤트를 중복 실행하지 않는가

## 13. 완성 판단

플레이어가 게임을 끝낸 뒤 다음 내용을 자신의 선택으로 설명할 수 있어야 한다.

- 왜 도박이 처음에는 매력적으로 보였는가
- 도박에 쓴 시간 때문에 무엇을 놓쳤는가
- 일상을 선택했을 때 무엇을 지킬 수 있었는가
- 손실을 복구하려는 선택이 왜 빚으로 이어졌는가
- 누구와의 관계가 어떤 선택 때문에 변했는가
- 문제를 숨기는 것과 도움을 요청하는 것이 어떻게 다른가

이 질문에 플레이 경험으로 답할 수 있을 때 일정관리와 시나리오가 하나의 게임으로 작동한 것이다.

## 14. 현재 적용 상태

- `Assets/Resources/ScenarioV3.csv`를 스토리의 단일 원본으로 사용한다.
- 73개 장면, 134개 대사, 53개 선택지가 7일 흐름과 네 엔딩에 연결되어 있다.
- 도박 사이트, 슬롯머신, 충전, 환전, SNS는 시작 흐름에서 비활성화되어 화면에 나타나지 않는다.
- 선택할 때마다 선택 ID, 장면, 일차, 시각, 선택 전후 상태가 `scenario_v3_history.json`에 저장된다.
- 메시지 장면은 메시지 앱의 실제 연락처와 채팅방에 쌓이며, 답장 선택도 채팅방에서 처리된다.
- 집, 학교, 카페, 수면, 도박 충동 장면은 2D 일러스트 배경으로 구분한다.
- 앱 열기, 메시지, 선택, 퀴즈 정답·오답에만 효과음을 사용하고 도박 연출 구간에만 전용 BGM을 사용한다.
- 일정 우선 경로와 도박 추격 경로를 Unity에서 실제 버튼으로 완주했고 각각 도움 요청 엔딩과 붕괴 엔딩을 확인했다.

현재 저장은 선택 이력과 상태 감사용이다. 게임을 다시 시작하면 저장 파일을 지우고 완전히 초기화하며, 중간 장면 이어하기 UI는 이번 제출 범위에 포함하지 않는다.
